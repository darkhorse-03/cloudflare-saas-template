Zynth uses [Alchemy](https://alchemy.run) for infrastructure-as-code deployment to Cloudflare's edge network.

## Prerequisites

1. [Cloudflare account](https://dash.cloudflare.com/sign-up)
2. Environment variables configured

## Authentication

Alchemy supports two authentication methods:

### Option 1: Browser OAuth (Recommended for local dev)

By default, Alchemy authenticates via browser OAuth. Just run:

```bash
bun run deploy
```

Alchemy will open your browser to authenticate with Cloudflare. No API token needed.

### Option 2: API Token (Required for CI/CD)

For automated deployments (GitHub Actions, etc.), create an API token:

1. Go to **Cloudflare Dashboard → My Profile → API Tokens → Create Token**
2. Select **Custom Token**
3. Add these permissions:

| Scope | Permission | Purpose |
|-------|------------|---------|
| Account → Workers Scripts | Edit | Deploy workers |
| Account → Workers KV Storage | Edit | Create KV namespaces (sessions) |
| Account → D1 | Edit | Create D1 databases |
| Account → Workers R2 Storage | Edit | Create R2 buckets (file storage) |
| Account → Cloudflare Queues | Edit | Create queues (background jobs) |
| Zone → DNS | Edit | Create DNS records |
| Zone → Zone | Read | Read zone info |

<Callout type="warn">
  Alchemy creates resources on first deploy. If your token lacks permissions, deployment will fail with `401 Unauthorized`. Create a token with **all** permissions above, even if you're not using all features yet.
</Callout>

**Quick setup**: Use the "Edit Cloudflare Workers" template as a starting point, then add D1, R2, Queues, and DNS permissions.

## Environment Variables

```bash
# Required
ALCHEMY_PASSWORD=xxx        # Encryption for Alchemy state (any string for local dev)

# Optional - only if using API token auth instead of browser OAuth
CLOUDFLARE_API_TOKEN=xxx    # API token with permissions above

# Optional - only if deploying to custom domain
CLOUDFLARE_ZONE_ID=xxx      # Zone ID from Cloudflare Dashboard → your-domain → Overview
```

<Callout type="info">
  If `CLOUDFLARE_API_TOKEN` is set, it overrides browser OAuth. Leave it unset for local development to use the simpler browser auth flow.
</Callout>

## Deploy

```bash
bun run deploy
```

This deploys all apps using their respective `alchemy.run.ts` configurations.

## Architecture

Zynth uses a multi-worker architecture:

| App | Route | Description |
|-----|-------|-------------|
| **Web** | `yourdomain.com` | Main React app |
| **API** | `yourdomain.com/api/*` | Hono API (via service binding) |
| **Docs** | `yourdomain.com/docs/*` | Documentation site |

### Service Bindings

The web worker proxies requests to other workers:

```ts title="apps/web/worker.ts"
// /api/* → API worker
if (url.pathname.startsWith('/api/')) {
  return env.api.fetch(new Request(apiUrl, request))
}
```

## Alchemy Configuration

Each app has an `alchemy.run.ts` file defining its infrastructure:

```ts title="apps/web/alchemy.run.ts"
import { DnsRecords, Vite } from 'alchemy/cloudflare'

// Create DNS record
await DnsRecords('web-dns', {
  zoneId: process.env.CLOUDFLARE_ZONE_ID,
  records: [
    {
      type: 'A',
      name: 'subdomain',
      content: '192.0.2.1',  // Proxied - actual IP doesn't matter
      proxied: true,
      ttl: 1,
    },
  ],
})

// Deploy Vite app
export const web = await Vite('web', {
  name: 'my-app-web',
  entrypoint: './worker.ts',
  bindings: { api },
  routes: [
    { pattern: 'yourdomain.com' },
    { pattern: 'yourdomain.com/*' },
  ],
})
```

## Custom Domains

### DNS Setup via Alchemy

DNS records are managed in code via `DnsRecords`:

```ts
await DnsRecords('my-dns', {
  zoneId: process.env.CLOUDFLARE_ZONE_ID,
  records: [
    {
      type: 'A',
      name: 'app',           // Creates app.yourdomain.com
      content: '192.0.2.1',  // Documentation IP (proxied)
      proxied: true,
      ttl: 1,
    },
  ],
})
```

<Callout type="info">
When `proxied: true`, Cloudflare intercepts traffic and routes to your Worker. The actual IP address doesn't matter—`192.0.2.1` is a documentation IP that's never routed.
</Callout>

### Route Configuration

Routes determine which Worker handles each URL pattern:

```ts
routes: [
  { pattern: 'yourdomain.com/docs' },
  { pattern: 'yourdomain.com/docs/*' },
]
```

More specific routes take precedence over wildcards.

## First Deployment

On first deploy:

1. Alchemy creates the D1 database and KV namespace
2. DNS records are provisioned
3. Workers are deployed with routes

After deploying, run migrations:

```bash
cd apps/api
bun run db:migrate:prod
```

## Docs Deployment

The docs app has special considerations:

1. **Base path**: Built with `base: '/docs/'` in Vite config
2. **Worker**: Strips `/docs` prefix before serving assets
3. **Search**: Prerendered to `/docs/api/search.json`
4. **Prerendering**: All pages must be listed in `vite.config.ts`

```ts title="apps/docs/vite.config.ts"
tanstackStart({
  spa: {
    enabled: true,
    prerender: { enabled: true, crawlLinks: true },
  },
  pages: [
    { path: '/' },
    { path: '/api/search' },
    { path: '/getting-started' },
    // ... all doc pages
  ],
})
```

<Callout type="warn">
TanStack Start SPA mode requires all pages to be explicitly listed for prerendering. `crawlLinks` alone may not discover all pages.
</Callout>

## CI/CD

For automated deployments, you need an API token (browser OAuth won't work in CI).

Example GitHub Actions workflow:

```yaml title=".github/workflows/deploy.yml"
name: Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v1
      - run: bun install
      - run: bun run build
      - run: bun run deploy
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ZONE_ID: ${{ secrets.CLOUDFLARE_ZONE_ID }}
          ALCHEMY_PASSWORD: ${{ secrets.ALCHEMY_PASSWORD }}
```

## Rollbacks

Cloudflare keeps deployment history. To rollback:

1. Go to Workers & Pages → your-app → Deployments
2. Click on a previous deployment
3. Click "Rollback to this deployment"

Or redeploy a previous git commit.
